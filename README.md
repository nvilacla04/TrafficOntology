## Project Description

This project analyzes traffic patterns and road safety in the Netherlands by integrating multiple open data sources, including Rijkswaterstaat accident data, NDW traffic flow and sensor data, and OpenStreetMap road network data.

We have designed and populated a unified knowledge graph to bridge the gap between these disconnected datasets. The graph provides a rich, queryable model linking accidents, road segments, sensors, traffic flow, and traffic signs, enabling complex analysis to answer key questions about road safety.

## Directory Structure

* **`/traffic-kg/`**: Contains the source files for our ontology (TBox), including our custom `traffic.ttl`, the imported `ontology.xml` (OTN), `geo.ttl` (GeoSPARQL), and `category_instances.ttl`.
* **`/data_rdf/`**: Contains the **final generated Knowledge Graph layers** as separate `.ttl` files (e.g., `road_network.ttl`, `accidents.ttl`, etc.). This folder also contains the enriched CSVs that were used as the direct source for generating these triples.
* **`/data_processed/`**: Contains all intermediate, cleaned CSV files that are the "clean" source for our pipeline (e.g., cleaned BRON data, merged sensor data).
* **`/data_raw/`**: Contains the original, untouched data (XMLs, shapefiles), including `OSM_data_filtered.gpkg` (the 390MB filtered OpenStreetMap dataset, which is the base map for our road network) and the initial exploratory/cleaning notebooks.
* **`/` (Root Directory)**:
    * `*.py`: Python scripts for the ETL (Extract, Transform, Load) pipeline.
    * `*.ipynb`: Jupyter Notebooks used for analysis and querying.
    * `requirements.txt`: All necessary Python dependencies.

## 2. Data Pipeline & Reproducibility

The final Knowledge Graph (`.ttl` files) is already provided in the `data_rdf/` folder.

If you wish to regenerate the entire Knowledge Graph from the processed CSVs and the GeoPackage, you must run the scripts in the root directory in this specific order, as they have dependencies:

1.  **`run_match_osm.py`**:
    * **Input:** `data_processed/BRON_cleaned/*.csv` and `data_raw/OSM_data_filtered.gpkg`.
    * **Output:** `data_rdf/accidents_enriched_osm_*.csv` files.
    * **Action:** Performs the complex spatial join to match each accident to its nearest OSM road segment based on name and coordinates.

2.  **`create_road_triples.py`**:
    * **Input:** `OSM_data_filtered.gpkg`.
    * **Output:** `data_rdf/road_network.ttl`.
    * **Action:** Generates RDF triples for all 905,321 road segments, including their types, properties (speed, surface), and geometries.

3.  **`create_accidents_triples.py`**:
    * **Input:** `data_rdf/accidents_enriched_osm_*.csv`.
    * **Output:** `data_rdf/accidents.ttl`.
    * **Action:** Generates triples for all accidents, linking them to their corresponding road segment (`traffic:occursOn`) and adding properties like severity, road condition, and involved vehicles.

4.  **`create_sensors_triples.py`**:
    * **Input:** `data_processed/merged/site_summary_with_coordinates.csv` and `OSM_data_filtered.gpkg`.
    * **Output:** `data_rdf/sensors.ttl`.
    * **Action:** Spatially joins sensors to roads and generates triples for each sensor, linking it to the road it monitors (`traffic:monitors`).

5.  **`create_traffic_flow.py`**:
    * **Input:** `data_processed/merged/traffic_flow_with_coordinates.csv` and `traffic_speed_with_coordinates.csv`.
    * **Output:** `data_rdf/traffic_flow.ttl`.
    * **Action:** Generates triples for time-series flow/speed measurements and links them to the sensors that recorded them (`traffic:measuredBy`).

6.  **`create_signs_triples.py`**:
    * **Input:** `data_processed/traffic_signs_by_type_cleaned/*.csv` and `OSM_data_filtered.gpkg`.
    * **Output:** `data_rdf/traffic_signs.ttl`.
    * **Action:** Spatially joins all 1.5M+ traffic signs to roads and generates triples for each, including its type (`rvvCode`), value (`signValue`), and link to the road (`traffic:hasTrafficSign`).

## 3. How to Load and Query the Knowledge Graph (GraphDB)

We recommend using **GraphDB (Free)** via Docker to host and query the graph.

### A. Run GraphDB

1.  **Pull the image:**
    ```bash
    docker pull ontotext/graphdb:10.6.3
    ```
2.  **Run the container:**
    ```bash
    docker run -d -p 7200:7200 --name my-graphdb ontotext/graphdb:10.6.3
    ```
3.  **Access:** Open `http://localhost:7200` in your browser.

### B. Create Repository

1.  Go to **Setup -> Repositories**.
2.  Click **Create new repository**.
3.  **Repository ID:** `TrafficOntology`
4.  **Ruleset:** `RDFS-Plus (Optimized)`
5.  Click **Create**.

### C. Import Knowledge Graph Layers

You must import the files in the correct order, each into its own **named graph**.

1.  Select your `TrafficOntology` repository.
2.  Go to **Import -> RDF -> Upload RDF files**.

3.  **Import Ontology Layer (TBox):**
    * **File:** `traffic-kg/traffic.ttl`
        * **Target graph:** `http://www.semanticweb.org/nicol/ontologies/2025/9/traffic`
    * **File:** `traffic-kg/ontology.xml`
        * **Target graph:** `http://ontology.eil.utoronto.ca/icity/OTN/`
    * **File:** `traffic-kg/geo.ttl`
        * **Target graph:** `http://www.opengis.net/ont/geosparql`
    * **File:** `traffic-kg/category_instances.ttl`
        * **Target graph:** `http://www.semanticweb.org/nicol/ontologies/2025/9/traffic/graph/categories`

4.  **Import Data Layer (ABox):**
    * Some of these files are too large for the web uploader. You must use the **"Server files"** import method.
    * **Step 1:** Copy the files into the Docker container.
        ```bash
        # Find your container ID
        docker ps
        # Create the import directory inside the container
        docker exec -it <YOUR_CONTAINER_ID> mkdir -p /root/graphdb-import
        # Copy all generated .ttl files
        docker cp data_rdf/. <YOUR_CONTAINER_ID>:/root/graphdb-import/
        ```
    * **Step 2:** In the GraphDB "Server files" tab, click the **Refresh** icon.
    * **Step 3:** Import each file one by one, assigning it a named graph:
        * **File:** `road_network.ttl` -> **Named graph:** `.../graph/roads`
        * **File:** `accidents.ttl` -> **Named graph:** `.../graph/accidents`
        * **File:** `sensors.ttl` -> **Named graph:** `.../graph/sensors`
        * **File:** `traffic_flow.ttl` -> **Named graph:** `.../graph/flow`
        * **File:** `traffic_signs.ttl` -> **Named graph:** `.../graph/signs`
